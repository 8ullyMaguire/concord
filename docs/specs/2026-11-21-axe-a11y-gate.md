# Spec: axe-core WCAG 2.1 AA route gate

## Problem
The 2026-11-20 sweep estimated contrast and tap targets but did not run a real accessibility engine. A visual pass cannot prove WCAG 2.1 AA, and a gate that cannot fail is decoration.

## Goals
- Run axe-core against representative Concord routes in a real browser.
- Cover both `prefers-color-scheme` values and both 1440px and 390px viewports.
- Prove the probe can fail with a canary violation before trusting a clean sweep.
- Wire the result into the repository gate and record any real violation with its rule id and nodes.

## Non-goals
- No claim of full-site certification: representative routes, not all 34, are in scope.
- No fix is applied speculatively; only violations axe actually reports are fixed.
- No user-supplied credential or production account.

## Constraints
- One targeted suite; no full-site hour-long run.
- axe-core is vendored locally so the gate has no network dependency.
- Builds/deploys in one tracked background job.

## Success criteria
- Canary: an injected unnamed button is reported by axe as `button-name`.
- Sweep: the selected routes produce zero WCAG 2.1 A/AA violations at both colour schemes and both widths, or every violation is fixed and re-proven.
- Public-host DOM probe confirms the live theme scheme changes computed colours and the gate line is recorded verbatim.
